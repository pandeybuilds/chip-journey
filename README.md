# chip-journey

> From zero to AI-hardware engineer. Built in public, one honest hour at a time.

## The mission

Become a master of electronics and semiconductors — a hardware expert who also codes —
targeting NVIDIA/Apple-grade work or eventually a semiconductor startup. The destination
is **AI accelerators and the physical bottlenecks of AI datacenters**.

**Track:** digital design + computer architecture spine, straddling the hardware/software
boundary (RTL → chip *and* CUDA/kernels), with RF/optical as a differentiating second barrel.

## The engine (how this actually works)

The plan is **build-first, recall-daily, ship-weekly**. Passive watching is banned — it's
why the first attempt failed. Every concept gets a thing I make.

**Weekday hour (Mon–Fri):**
- `0:00–0:10` **Recall** — Anki review (see [`anki/`](anki/)). Non-negotiable.
- `0:10–0:55` **One unit** — read-and-build a single chunk. Keyboard always active.
- `0:55–1:00` **Log** — one line in today's [`log/`](log/) entry + commit.

**Weekend — Build block (~3 hrs):** ship the week's artifact (a circuit, a passing
testbench, a module that runs). One shippable thing per week.

**Weekend — Light (~40 min):** write the week's build-log in my own words, make Anki
cards, plan next week. Then rest.

## The five rules

1. **Build-first, always.** No concept without an artifact.
2. **Never break the chain — but allow a Minimum Viable Day** (just the 10-min Anki counts).
3. **Active recall over re-reading.** Anki daily; teach it back in the log.
4. **Ship weekly, build in public.** This repo is the proof.
5. **Prioritize ruthlessly.** The track is *digital*. When in doubt, cut analog/tangents.
